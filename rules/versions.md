## 1.2.1 — 2026-11-11 — 웹 계정 비밀번호 최소 8자

## 1.2.0 — 2026-11-11 — OS·커널 및 설치 RPM 명세

- 로컬 JAR·원격 SSH가 공유하는 고정 셸 수집기로 `uname -a/-r/-v/-m`, `/etc/os-release`, `/etc/redhat-release`, `/proc/version`을 수집한다. 항목당 16 KiB로 제한하고 배포판과 실행 커널을 구분한다.
- 설치 RPM의 이름·Epoch·버전·Release·아키텍처·NEVRA를 보존한다. 여러 설치 버전/아키텍처를 합치지 않는다. 읽기 전용 조회에 20초·20,000건·4 MiB 제한을 적용하고 도구 없음·권한/DB 실패·시간 초과·부분 수집을 기록한다.
- 호스트 OS/RPM 명세를 서비스 직군 명세와 분리하고 웹 상세·JSON·Markdown·XLSX에 추가한다. XLSX는 CLI 32개·웹 33개 시트이며 ZIP은 26개 파일이다. 웹 RPM 목록은 첫 100건을 표시하고 전체 수집 목록은 다운로드한다.
- 이전 JSON 스냅샷을 `미수집` 상태로 읽는 호환성을 유지한다. 새 DB 마이그레이션은 없다. RPM 설치 여부는 실행 서비스 사용이나 CVE 판정이 아니며 RPM CVE 대조·컨테이너별 RPM DB는 미지원이다.
- 중앙 구현 언어를 자원 실측에 따라 선택할 수 있도록 지침을 변경했다. 이번에는 Spring Boot를 유지하고 유휴 관측·작은 SSH 시험의 자원 사용과 Python 등 전환 검토 조건을 `docs/runtime-decision.md`에 기록했다. 목표 최대 부하와 Python 대조 구현은 측정하지 않았다.
- JDK 21.0.13+9 `./mvnw verify`: **69개 테스트 통과**. OS/RPM 파싱·다중 버전·이전 스냅샷·없는 도구·실패·시간 제한·행/바이트 제한·수식 유사 문자열·보고서 원문 보존 포함.

## 1.1.0 — 2026-11-11 — SSH 인증·root 점검·화면 가독성

- 기존 키 기반 대상의 호환성을 유지하는 인증·권한 옵션 추가로 중 버전을 올린다. DB V3 마이그레이션은 기존 대상을 KEY/NONE으로 보존한다.
- SSH password 인증, 암호화된 개인 키의 암호 입력, su root 비밀번호·sudo 비밀번호·NOPASSWD sudo 선택. 자격 증명 암호화·조회 제외·미사용 비밀값 제거.
- 관리자 호스트 공개 키 조회·SHA-256 지문 확인, .pub/known_hosts 한 줄과 주석 입력. 접속 인증과 별도로 호스트 검증 유지.
- root 전환에서 TTY·에코 차단·단일 비밀번호 전달·UID 0 확인. 실행 계정과 UID를 보고서에 기록하고 전환 실패는 점검 실패로 처리한다.
- 한글 Noto Sans KR·영문 JetBrains Mono와 라이선스·해시를 앱에 포함. 본문·입력 18px, 표·설명 16px와 넓은 폼으로 조정한다.

### 폐쇄망 반입 묶음 — 개정 1 / 2026-11-11

- 대상 환경은 사용자가 확인한 Linux x86_64, Docker Engine·Compose 설치 완료 서버. 앱 바이너리는 기존 `v1.0.0` / `4075915`와 동일하며 기존 릴리스 태그를 유지한다.
- `scripts/package-offline.py`와 `deployment/offline/`로 앱·PostgreSQL 18.6의 amd64 이미지 전체, Maven ZIP 7,257건, CCE/정책 JSON, 소스 스냅샷, 설치·운영 스크립트와 한국어 안내를 묶는다. 산출물은 Git 제외 `resources/offline/`에 보관한다.
- SHA-256으로 파일을 확인하고 `docker load`로 설치한다. 이미지 저장 방식에 따라 바뀔 수 있는 표시용 ID 대신 실행 설정·파일시스템 레이어 해시를 대조한다. 빌드·pull 없이 기동하고 현장에서 새 비밀번호·암호화 키를 생성한다. 기존 `.env`·DB·계정·SSH 키·보고서는 제외한다.
- Docker Engine 29.9.3 / Compose 5.7.0에서 두 이미지 재반입, 새 DB 초기화와 관리자 로그인 확인. `internal: true` 시험 네트워크에서 외부 연결 실패와 앱/DB 정상 기동을 확인하고 동봉 ZIP을 반영해 CVE/OSV 7,257건·CCE 2건·정책 1건을 조회했다.
- 반복 초기화 시 `.env` 보존·권한 600·32바이트 암호화 키 생성 확인. 중지·재시작 및 컨테이너 재생성 후 계정·카탈로그·갱신 이력 보존과 localhost 웹 접속 확인. 셸·Python 문법 및 Compose 설정 검사 통과.
- 최종 압축 파일을 다시 풀어 내부 파일 전체의 SHA-256과 파일 목록을 확인했다. 반입 묶음은 317,942,272바이트이며 전체 SHA-256은 `b3fd9c6b473da15bbecff435156fa4e73876c068765dfa09dfdeac9f88d32be5`이다.
- 별도로 만든 시험 프로젝트·DB는 검증 후 정리하고 기존 서비스·DB의 정상 상태를 확인했다. 실제 폐쇄망 서버에서는 아직 실행하지 않았으며 ARM64·구버전 Compose·해당 조직의 SSH/방화벽 구성은 이 검증에 포함하지 않는다.

### 현재 한계

- 원격 기본 지원은 Linux SSH 공개 키 인증이다. Windows, Kubernetes/containerd, OS/비 Java 패키지의 자동 CVE 대조, Docker 이미지 전체 레이어 스캔은 미지원.
- CCE는 등록된 OS·허용된 설정 규칙 범위만 판정하며 SCAP 전체 준수 인증을 대체하지 않음. `sshd -T`는 전역 값이며 Match 블록별 연결 설정은 미판정.
- 애플리케이션은 단일 인스턴스 기준이다. 다중 인스턴스 작업 큐, 계정별 대상 격리, 비밀번호로 보호된 SSH 개인 키, 비밀번호 SSH 인증은 후속 범위.
- Maven 반입 데이터는 현재 PC의 DB/반입 폴더에 있으며 소스 저장소에는 기본 5건과 준비 스크립트만 포함한다. 폐쇄망 신규 배포 시 운영 데이터 ZIP도 함께 반입한다.
