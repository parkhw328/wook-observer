## 1.11.0 — 2026-11-17 — 구형 서버 수집·OS 전환 표시·서비스 분류

- RHEL·CentOS 7.x의 procps-ng 3.3.10에서 쉼표 출력 구문이 PID만 남겨 반입이 거부되는 문제를 재현하고, 프로세스·JVM 조회를 개별 `-o` 인자로 수정했다. 기본 프로세스 필드가 없으면 SH가 성공 파일을 남기지 않으며 업로드 오류에서 재수집을 안내한다.
- RPM 4.11의 미지원 MODULARITYLABEL 태그를 조건부 제외하고 빈 결과를 정상 완료로 오인하지 않는다. 구형 ss는 헤더를 제거해 읽고, hostname 없는 최소 환경은 uname으로 보완한다. 선택 도구·Python 상세 수집 실패와 기본 자산 등록을 분리하고 도메인 사용자 이름을 허용한다. 무결성·완료·크기·건수·UTF-8 검증은 유지한다.
- 유효한 이전 파일의 HOST 이름 누락은 수집된 uname 근거가 있을 때만 복원한다. PID만 남아 상세 프로세스 근거가 없는 파일은 복원하지 않고 최신 SH 재수집을 안내한다. 원본 업로드 데이터는 수정하지 않는다.
- 수집 OS 근거로 RHEL·CentOS 7.x를 식별해 대시보드 대상 수/필터·목록 배지·상세·미리보기·MD/XLSX에 **OS 업그레이드 필요**를 표시한다. CentOS EOL과 RHEL 정규 유지보수 종료를 구분하고 RHEL 7.9 ELS 조건·계약 미확인, 공식 출처·정책 확인일·표시 기준일을 제공한다. 다른 OS를 지원 중으로 추정하지 않으며 CVE 건수와 분리한다. RPM CVE 판정 범위는 기존 8/9/10을 유지한다.
- 기동 시 기존 최근 점검의 OS 근거로 자산 표시 정보를 보완한다. 원본 보고서·당시 판정·수기 프로필·운영 절차를 유지하며 DB 마이그레이션은 추가하지 않는다.
- 서비스 등록/편집 구분에 웹 서버·데이터베이스·컨테이너·캐시·메시징·인프라를 추가했다. 기존 분류와 수기 값을 유지하고 저장·재점검·표·MD/XLSX의 분류명을 일치시킨다.
- Maven verify **140개**, Node **11개**, Python **6개**를 통과했다. 로컬/이미지 JAR의 압축 해제 항목 377개와 모든 런타임 리소스가 일치한다.
- CentOS 7.9 도구 환경에서 프로세스 8개·RPM 154개·실제 TCP/UDP 소켓 2개, Red Hat UBI 7.9 최소 환경에서 프로세스 7개·RPM 164개를 수집해 실제 API 반입을 검증했다. 컨테이너는 호스트 커널을 공유하므로 물리 RHEL 7 서버 전체 검증과 구별한다. 사용자 오류 원본 파일은 제공되지 않았으며 별도 재현 환경을 사용했다.
- 별도 PostgreSQL 18.6에서 1.10.1 → 1.11.0 업그레이드 후 수기 정보·서비스·원본 보고서와 기존 OS 근거를 보존했다. 실제 이미지의 Chromium에서 종료 대상 필터/미리보기, 손상 파일 거부·중복 방지, ADMIN/USER 표시, 1920/1440/1100/960/741/740/390px·200% 확대, 새 분류의 모달 저장/재조회·MD/XLSX를 확인했다. 스크립트 오류·외부 자산 요청은 없다.
- 화면·실측·검증 근거는 Git 제외 `resources/asset-1.11.0-check/`에 보관한다. 시험 컨테이너·네트워크는 제거했고 기존 운영 1.4.0 앱·DB는 변경하지 않았다.

- 호스트·프로세스·JVM 선별 속성·Java 라이브러리·Docker 컨테이너 수집 및 호스트 PID 연결.
- 일반 JAR, 묶음 JAR의 Maven 메타데이터, Spring Boot/WAR 중첩 라이브러리 조사. 컨테이너 루트의 파일은 네임스페이스 경로를 유지해 조회.
- 일곱 서비스 직군별 프로세스·오픈소스·컨테이너 명세와 분류 근거·설정 지원. 요약·JSON 포함 총 23개 문서 생성.
- 로컬 HTTP API, ZIP 다운로드, 일회성 폴더 출력. 동시 분석은 HTTP 409로 응답하고 기존 출력 폴더는 덮어쓰지 않음.
- 읽기 중심 조회, 허용된 JVM 속성만 출력, 조회 시간·출력·JAR 메타데이터 제한과 부분 실패 기록.
- Maven Wrapper, `.editorconfig`, `.gitignore`, README 및 JUnit 테스트 구성. `resources/`, `reports/`, `target/`, `.tools/`는 Git 제외.

### 검증

- Temurin JDK **21.0.13+9**에서 `./mvnw verify` 성공: **36개 테스트 통과**, 실패·오류·건너뛴 테스트 없음.
- 기본 환경의 JDK 21.0.12.1에서는 Maven 빌드와 JAR 실행이 모두 차단되는 것을 확인.
- 실제 JAR의 HTTP 기동, `/actuator/health`, 명세 ZIP 다운로드 및 내부 문서 링크 확인.
- 최종 일회성 실행: 프로세스 **799개**, Java 프로세스 **3개**, Docker 컨테이너 **28개**, 컨테이너 연결 프로세스 **300개**, 라이브러리 항목 **294개**, 수집 오류 **0개**.
- 라이브러리 항목 수는 프로세스별 합계로 중복 라이브러리를 포함한다. 위 수치는 검증 당시 스냅샷이며 실행 시 달라진다.
- 컨테이너 내부 실행 JAR의 라이브러리 읽기, 직군별 문서 23개 생성, 문서 링크, 공유 폴더 제외 및 공백 검사 확인.
- 검증용 JDK는 로컬 `.tools/jdk-21.0.13+9`에 보관. 시스템 기본 Java 설정은 변경하지 않음.

### 남은 범위

- 비 Java 런타임·OS 패키지 상세, 라이선스/SBOM/취약점, 동적 로딩 증명, systemd·호스트 리스닝 포트·서비스 호출 관계, 원격/Kubernetes 계층은 후속 요구사항이다.
- 기본 자동 분류는 실행 파일/이미지 이름 휴리스틱이며 설정 보정이 필요할 수 있다. 수집 오류가 없더라도 미지원 범위까지 분석한 것은 아니다.
- 현재 변경 사항과 실행 JAR는 로컬 작업공간에 준비되어 있으며 GitHub 릴리스는 발행하지 않았다.
