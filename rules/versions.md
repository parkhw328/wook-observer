# 버전 이력

버전 형식은 `대.중.소`이며 정책은 [rules.md](rules.md)를 따른다.

## 1.0.0 — 2026-11-11 — Docker 웹 플랫폼 및 내부 취약점 관리

- 이전 0.1.0·0.2.0 커밋을 GitHub `main`에 푸시한 후 웹서비스 전환 진행. 기본 실행 방식과 인증 API가 바뀌므로 대 버전을 올림.
- Spring Boot 웹 화면·세션 인증·CSRF 보호, ADMIN/USER 관리, 계정 추가·권한/비밀번호 변경·비활성화·기존 세션 만료·마지막 관리자 보호.
- PostgreSQL 18.6과 Flyway, Docker Compose 앱/DB, 비루트 앱·영속 DB 볼륨·상태 검사. JDK/JRE 21.0.13+9 이미지 사용.
- SSH 대상 등록·수정, AES-256-GCM 자격 증명 저장, 필수 호스트 키 확인, 비동기 점검·대기열·이력·재시작 시 미완료 작업 기록.
- 대상 Java 설치를 요구하지 않는 Linux 기본 점검. 접근 가능한 Docker CLI와 jcmd/Python 3·파일 권한에 따라 컨테이너·JVM·JAR 메타데이터 추가 수집.
- OSV JSON/ZIP 및 CCE/POLICY 묶음을 내부 DB에 저장. 전체 검증·원자적 갱신·철회/이전 수정본 처리·출처·개정 번호·SHA-256·성공/실패 이력.
- 관리자에서 파일 반입, 반입 폴더/허용된 내부 HTTPS 미러, 6필드 cron·시간대·즉시 갱신을 설정. 기본 정기 실행은 비활성화.
- Maven 버전 범위와 명시적인 플랫폼/설정 규칙을 대조하고 발견·의심·미발견·점검 불가를 구별. 동일 권고의 여러 영향 범위는 라이브러리별 한 결과로 통합.
- 동일 스냅샷을 DB에 보존하고 XLSX·ZIP·JSON·요약 MD 재다운로드. 직군별 명세에 `취약점발견` 컬럼, 웹 XLSX에 취약점 상세 시트를 추가하여 **31개 시트** 제공.
- 기존 일회성 JAR와 loopback 전용 collector HTTP 프로필 유지. CLI는 DB 대조 없이 기존 30개 시트와 `미실시` 상태를 제공.
- 시작용 목록은 CVE 2건·RHEL CCE 2건·내부 Docker 정책 1건. 별도 준비 스크립트로 공식 OSV Maven 전체 덤프를 반입할 수 있으며 데이터 파일은 Git 제외.

### 검증

- JDK 21.0.13+9의 `./mvnw verify`: **54개 테스트 통과**, 실패·오류·건너뜀 없음. 인증·CSRF·권한·세션 폐기·키 암호화·보고서·버전 경계·CCE 적용 OS·데이터 원자성·철회·잘못된/과대 ZIP·예약 실행 포함.
- 실제 Docker 이미지 빌드, PostgreSQL 마이그레이션과 앱/DB 정상 상태 확인. 앱 교체 후 대상·계정·점검 이력·카탈로그 보존 확인.
- PostgreSQL 컨테이너를 재생성한 후에도 영속 볼륨의 카탈로그 7,260건과 관리자 계정이 보존되는 것을 확인. 검증용 대상·계정·컨테이너는 정리하고 운영용 앱/DB는 유지.
- Java 미설치 SSH 시험 컨테이너에서 프로세스 **6개**, JVM **0개** 수집과 보고서 다운로드 성공. Docker 접근 불가 등 수집 제한을 기록.
- 별도 JDK 21.0.13 시험 프로세스와 합성 Maven `log4j-core:2.14.1` 메타데이터에서 프로세스 **7개**, JVM **1개**, 라이브러리 **1개** 수집. 초기 목록에서는 CVE 2건, Maven 덤프 반입 후에는 저장 기준상 CVE **8건** 일치. 실제 Log4j 실행 코드나 운영 취약점을 확인한 결과가 아님.
- 공식 OSV Maven ZIP **10,539,999바이트 / 7,257건**을 현재 PC의 PostgreSQL에 반영. 데이터 기준 마지막 수정 시각은 2026-11-10 19:48:24 UTC, 취득일은 2026-11-11. CCE 2건·내부 정책 1건을 포함한 총 7,260개 카탈로그 레코드 보관.
- 해당 ZIP SHA-256: `f779994d544de75b9a303de907d2bbe91dc7936f7ca060208f92828e207577a3`. 다운로드 manifest와 DB 갱신 이력에 출처·해시 기록.
- 실제 PostgreSQL에서 UI 파일 반입, 예약 갱신, 실패 시 카탈로그 유지, 사용자 비활성화 확인. 올바르지 않은 SSH 호스트 키를 사용한 연결이 실패하는 것을 확인.
- Playwright로 로그인·대상 등록·점검·내려받기·CVE alias 검색·사용자 관리·권한 제한과 데스크톱/모바일 레이아웃 확인. 브라우저 스크립트 오류 없음.
- openpyxl로 XLSX **31개 시트**, ZIP **24개 파일**, 원문 **23개** 복원 일치·취약점 컬럼/상세·수식 셀 부재 확인. 기존 CLI의 DB 없는 일회성 출력도 확인.
- 시험 보고서와 화면은 Git 제외 `resources/web-platform-check/`에 보관. 실제 SSH 테스트는 격리된 Linux 대상이며 Docker 소켓을 제공하지 않음. Docker 응답·PID 네임스페이스 경계는 fixture와 기존 수집기 테스트로 검증.

### 현재 한계

- 원격 기본 지원은 Linux SSH 공개 키 인증이다. Windows, Kubernetes/containerd, OS/비 Java 패키지의 자동 CVE 대조, Docker 이미지 전체 레이어 스캔은 미지원.
- CCE는 등록된 OS·허용된 설정 규칙 범위만 판정하며 SCAP 전체 준수 인증을 대체하지 않음. `sshd -T`는 전역 값이며 Match 블록별 연결 설정은 미판정.
- 애플리케이션은 단일 인스턴스 기준이다. 다중 인스턴스 작업 큐, 계정별 대상 격리, 비밀번호로 보호된 SSH 개인 키, 비밀번호 SSH 인증은 후속 범위.
- Maven 반입 데이터는 현재 PC의 DB/반입 폴더에 있으며 소스 저장소에는 기본 5건과 준비 스크립트만 포함한다. 폐쇄망 신규 배포 시 운영 데이터 ZIP도 함께 반입한다.

## 0.2.0 — 2026-11-11 — XLSX 통합 보고서 구현 및 검증 완료

- 0.1.0 초기 소스를 로컬 커밋 `f453a20`으로 기록.
- Apache POI 6.0.0 기반 `report.xlsx` 생성. 요약·호스트·직군별 현황·JVM 속성·컨테이너 연결·수집 오류·직군별 명세·원문을 **30개 시트**에 통합.
- 기존 Markdown 22개와 JSON 1개의 내용을 원문 시트에 분할 보존하고 UTF-8 크기·SHA-256·조각 위치를 제공.
- 기존 폴더 출력·ZIP에 XLSX를 추가하여 총 **24개 파일** 제공. `POST /api/v1/reports.xlsx`로 단독 다운로드 지원.
- 필터·고정 헤더·내부 이동 링크·인쇄 설정과 기본 스타일 제공. 수집 문자열을 수식으로 실행하지 않으며 15자리 초과 정수와 긴 Unicode 원문을 보존.
- XLSX는 기존 MD·JSON과 동일 스냅샷으로 생성한다. 긴 표의 값은 미리보기로 축약하고 JSON 원문에 전체 값을 남긴다.

### 검증

- JDK 21.0.13+9에서 `./mvnw verify` 성공: **43개 테스트 통과**, 실패·오류·건너뛴 테스트 없음.
- 테스트에서 직군별 명세·요약 집계·내부 링크·원문 복원·빈 결과·긴 한글/이모지·숫자 정밀도·수식 해석 방지·파일/ZIP/API 제공 확인.
- 최종 JAR로 실제 PC 점검: 프로세스 **800개**, Java 프로세스 **3개**, Docker 컨테이너 **28개**, 라이브러리 항목 **306개**, 수집 오류 **0개**. 항목 수는 검증 당시 스냅샷이며 라이브러리는 프로세스별 중복과 수집기 자체를 포함한다.
- 별도 openpyxl 읽기로 XLSX의 모든 원문 23개를 파일과 대조하고 SHA-256·집계·직군별 행·필터·고정 헤더를 검증. 파일 읽기 경고 없음.
- 실제 JAR의 XLSX 단독 다운로드 HTTP 200과 30개 시트 확인. LibreOffice에서 실제 파일을 열고 출력 형태 확인.
- 공유용 XLSX와 전체 ZIP은 Git에서 제외된 `resources/`에 보관. `AGENTS.md`와 0.1.0 점검 산출물은 보존.

## 0.1.0 — 2026-11-11 — 초기 구현 및 로컬 검증 완료

- JDK 21.0.13 이상인 Java 21 계열과 Spring Boot 4.1.2 기반 실행 JAR 구성. Maven 빌드와 애플리케이션 시작 시 버전 검사.
- 호스트·프로세스·JVM 선별 속성·Java 라이브러리·Docker 컨테이너 수집 및 호스트 PID 연결.
- 일반 JAR, 묶음 JAR의 Maven 메타데이터, Spring Boot/WAR 중첩 라이브러리 조사. 컨테이너 루트의 파일은 네임스페이스 경로를 유지해 조회.
- 일곱 서비스 직군별 프로세스·오픈소스·컨테이너 명세와 분류 근거·설정 지원. 요약·JSON 포함 총 23개 문서 생성.
- 로컬 HTTP API, ZIP 다운로드, 일회성 폴더 출력. 동시 분석은 HTTP 409로 응답하고 기존 출력 폴더는 덮어쓰지 않음.
- 읽기 중심 조회, 허용된 JVM 속성만 출력, 조회 시간·출력·JAR 메타데이터 제한과 부분 실패 기록.
- Maven Wrapper, `.editorconfig`, `.gitignore`, README 및 JUnit 테스트 구성. `resources/`, `reports/`, `target/`, `.tools/`는 Git 제외.

### 검증

- Temurin JDK **21.0.13+9**에서 `./mvnw verify` 성공: **36개 테스트 통과**, 실패·오류·건너뛴 테스트 없음.
- 기본 환경의 JDK 21.0.12.1에서는 Maven 빌드와 JAR 실행이 모두 차단되는 것을 확인.
- 실제 JAR의 HTTP 기동, `/actuator/health`, 명세 ZIP 다운로드 및 내부 문서 링크 확인.
- 최종 일회성 실행: 프로세스 **799개**, Java 프로세스 **3개**, Docker 컨테이너 **28개**, 컨테이너 연결 프로세스 **300개**, 라이브러리 항목 **294개**, 수집 오류 **0개**.
- 라이브러리 항목 수는 프로세스별 합계로 중복 라이브러리를 포함한다. 위 수치는 검증 당시 스냅샷이며 실행 시 달라진다.
- 컨테이너 내부 실행 JAR의 라이브러리 읽기, 직군별 문서 23개 생성, 문서 링크, 공유 폴더 제외 및 공백 검사 확인.
- 검증용 JDK는 로컬 `.tools/jdk-21.0.13+9`에 보관. 시스템 기본 Java 설정은 변경하지 않음.

### 남은 범위

- 비 Java 런타임·OS 패키지 상세, 라이선스/SBOM/취약점, 동적 로딩 증명, systemd·호스트 리스닝 포트·서비스 호출 관계, 원격/Kubernetes 계층은 후속 요구사항이다.
- 기본 자동 분류는 실행 파일/이미지 이름 휴리스틱이며 설정 보정이 필요할 수 있다. 수집 오류가 없더라도 미지원 범위까지 분석한 것은 아니다.
- 현재 변경 사항과 실행 JAR는 로컬 작업공간에 준비되어 있으며 GitHub 릴리스는 발행하지 않았다.
