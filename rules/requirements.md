# 요구사항

## 목적

서버에서 실행 중인 서비스의 여러 계층을 조사하여 운영자가 검토할 수 있는 명세 문서로 제공한다. Java 소스 정적 분석이 아니라 **실행 환경과 실행 중인 서비스 분석**이 중심이다.

## 1.0.0 구현 범위

상태: 아래 초기 범위의 구현 및 로컬 검증 완료. 확인 결과는 [versions.md](versions.md)에 기록한다.

- Docker Compose의 중앙 앱·PostgreSQL, Flyway 스키마, DB 영속 볼륨, 비루트 앱 이미지.
- 세션/CSRF 로그인, ADMIN/USER, 계정 변경에 따른 세션 폐기와 마지막 관리자 보호.
- SSH 키 암호화·호스트 키 확인, Linux 대상 등록·변경, 동시 2개 점검과 최대 16개 대기 작업, 재시작 시 미완료 작업 기록.
- Java 없는 Linux의 OS·프로세스 수집. Docker CLI·권한이 있으면 컨테이너 조사. jcmd/Python 3·읽기 권한에 따른 JVM·JAR 상세 조사.
- 저장한 스냅샷의 XLSX·ZIP·JSON·요약 MD 다운로드. 웹 XLSX는 취약점 상세를 포함한 31개 시트.
- OSV JSON/ZIP 및 명시적인 CCE/POLICY 규칙 반입. 단일 묶음 검증·트랜잭션 갱신·철회/이전 버전 반입 처리·SHA-256 기록.
- 관리자에서 반입 파일 또는 허용된 내부 HTTPS 미러, 6필드 cron·시간대, 즉시 갱신·성공/실패 이력 관리.
- 초기 목록은 공식 출처 CVE 2건, RHEL CCE 2건, 내부 Docker 정책 1건. 전체 취약점 데이터는 운영자가 반입한다.
- 외부 준비 환경에서 공식 OSV Maven 덤프를 받는 스크립트 제공. 현재 PC의 DB에는 2026-11-11 취득한 Maven 권고 7,257건을 실제 반입해 검증했다. 이 운영 데이터는 Git에 포함하지 않는다.
- CVE 자동 판정은 Maven 좌표/버전의 지원 OSV 범위에 한정한다. CCE는 구현된 설정 키와 OS 적용 기준이 있는 규칙만 실행한다.

REQ-012~018은 위 초기 범위로 수용하며 Windows·다중 앱 인스턴스·전체 생태계 취약점 분석·완전한 SCAP 준수 검증은 포함하지 않는다. 0.2.0의 기본 HTTP 사용 방식이 인증된 웹 플랫폼으로 바뀌므로 대 버전을 올린다. 기존 CLI와 loopback 전용 HTTP collector 프로필은 유지한다.

## 0.2.0 구현 범위

상태: 구현 및 로컬 검증 완료. REQ-011의 수용 기준을 검증했으며 세부 결과는 [versions.md](versions.md)를 따른다.

- `report.xlsx`에 요약·호스트·직군별 현황·JVM 속성·컨테이너 연결·수집 오류와 직군별 세 종류의 명세를 수록.
- 기존 Markdown 22개와 JSON 1개의 원문을 파일별로 보존. 긴 내용은 번호를 붙여 나누며 이어 붙여 복원할 수 있어야 함.
- 기존 CLI 폴더와 ZIP 응답에 XLSX를 추가하고 `POST /api/v1/reports.xlsx`로 단독 다운로드.
- 워크북의 집계·상세 행·원문을 원본 보고서와 대조하고, 긴 Unicode 텍스트·숫자 정밀도·수식으로 해석될 수 있는 문자열·빈 결과를 검증.

## 0.1.0 구현 범위

상태: 초기 구현 및 로컬 검증 완료. 아래 범위에 대한 세부 검증은 [versions.md](versions.md)를 따른다.

- Linux `/proc`와 Java Process API를 통한 프로세스 스냅샷.
- 허용된 `jcmd` 조회 및 실행 JAR/클래스패스의 라이브러리 메타데이터. Spring Boot 중첩 JAR 포함.
- Docker CLI의 조회 명령과 `docker top`을 통한 내부 프로세스 연결. 컨테이너 파일은 접근 가능한 `/proc/<pid>/root`를 통해 조회.
- Markdown 명세 묶음과 JSON 보고서, 로컬 HTTP API와 일회성 보고서 생성 모드.
- 서비스 직군 자동 분류와 설정을 통한 명시적 분류.

REQ-001~003과 REQ-008~010의 초기 수용 기준을 구현했다. REQ-004~007은 아래 후속 확장 항목과 접근 권한에 따른 한계가 남아 있으며 전체 계층의 완전한 분석을 완료한 것으로 보지 않는다.

## 후속 확장 범위

- TCP/UDP 리스닝 포트와 프로세스의 연결, systemd 유닛과 서비스 종속 관계.
- 비 Java 런타임 및 OS 패키지의 상세 버전·라이선스·SBOM, 해당 생태계의 취약점 자동 대조.
- JVM 동적 클래스 로더와 실제 로딩 라이브러리 증명, JMX 지표, 서비스 호출 관계.
- Windows 원격 서버, Docker 이미지 레이어 전체 분석, Kubernetes·containerd 등 추가 런타임, PDF 출력.

## 수집 한계와 수용 기준

- 설치된 라이브러리의 존재와 JVM에 실제 로딩된 사실은 구분한다. 버전·라이선스 미확인은 그대로 표시한다.
- 권한, PID/마운트 네임스페이스, attach 비활성화, 누락된 도구에 따른 제한을 기록한다. 모든 계층을 지원하는 방향으로 확장하며 미구현 항목을 완료로 표시하지 않는다.
- JDK 최소 버전 검사, 패키징, JAR 기동, 건강 상태 확인, 명세 생성, 민감정보 제외, 수집 실패 처리를 검증한다.
- 실제 검증 범위와 구현 상태는 `versions.md`에 기록한다.
