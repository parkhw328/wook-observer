# 요구사항

## 목적

서버에서 실행 중인 서비스의 여러 계층을 조사하여 운영자가 검토할 수 있는 명세 문서로 제공한다. Java 소스 정적 분석이 아니라 **실행 환경과 실행 중인 서비스 분석**이 중심이다.

## 1.3.0 구현 범위

- 비밀번호 로그인 기본, 공개 키 수동 입력은 선택 설정. 대상 저장 시 서버 지문을 자동 조회하고 확인 후 등록한다. 기존 대상은 저장된 키·지문을 표시하고 주소/포트/조회 키 변경 시 재확인한다.
- 서버 호스트 키는 접속 인증과 별도로 저장·검증한다. 인증 실패나 호스트 키 변경 시 검증을 건너뛰지 않는다.
- 주황색·밝은 중립 배경으로 로그인/대시보드/대상/관리 화면을 통일하고, 관측 렌즈 SVG 로고와 여섯 메뉴의 SVG 아이콘을 제공한다.
- 1.0.0 일반 고딕체 계열로 복원하되 본문·입력 18px, 표·설명 16px는 유지한다. 로컬 Noto Sans KR 대체 글꼴로 폐쇄망에서 표시한다.
- 1.2.1의 최소 8자 웹 계정 비밀번호 변경을 함께 제공한다. 기존 DB 스키마·저장된 비밀번호·대상·보고서를 유지한다.

## 1.2.1 구현 범위

- 최초 관리자 생성, 사용자 추가, 비밀번호 변경의 최소 길이를 12자에서 8자로 변경하고 화면·오류 메시지·설치 안내를 일치시킨다.
- 기존 계정·비밀번호·암호화 키·DB 스키마는 유지한다. `.env`의 초기 비밀번호는 신규 DB에만 적용하며 기존 계정은 사용자 관리에서 변경한다.
- 7자 거부·8자 허용·UTF-8 72바이트 상한·빈 편집 유지·세션 만료를 검증하고 1.2.1 폐쇄망 이미지를 제공한다.

## 1.2.0 구현 범위

- 고정된 읽기 전용 셸 수집기를 로컬 JAR과 SSH에서 공유. OS 기본 명령과 릴리스 파일(항목당 16 KiB), RPM 조회(20초·20,000건·4 MiB)를 제한한다.
- RPM 없는 환경, 권한/DB 실패, 시간 제한, 일부 수집을 구분하고 다중 아키텍처·설치 버전을 보존한다. 대상에 Java·Python·RPM을 자동 설치하지 않는다.
- `host/os.md`, `host/rpm-packages.md`, JSON의 `systemInventory`, XLSX의 OS·커널/RPM 패키지 시트와 웹 상세. XLSX는 CLI 32개·웹 33개 시트, ZIP은 26개 파일이다.
- 기존 저장 스냅샷은 OS/RPM `미수집`으로 읽고 다운로드한다. 새 필드는 재점검부터 채워지며 DB 마이그레이션은 필요 없다.
- RPM 설치 목록은 서비스별 라이브러리와 구분한다. RPM CVE 대조·컨테이너별 RPM DB 수집은 이번 범위에 포함하지 않는다.
- 현재 유휴 자원 측정과 전환 판단은 [runtime-decision.md](../docs/runtime-decision.md)에 기록한다. Java 유지 여부를 고정 규칙으로 삼지 않는다.

## 1.1.0 구현 범위

- 기존 대상은 KEY/NONE 방식으로 이관한다. 비밀번호·키 암호·root/sudo 비밀번호를 암호화하고 조회에서 제외한다.
- ADMIN의 호스트 키 조회와 지문 확인, .pub/known_hosts 주석 입력, 선택한 인증 방식에 맞는 대상 등록 폼.
- 접속 계정 그대로, root 비밀번호 su, sudo 비밀번호, NOPASSWD sudo. 실제 UID 0 확인 후 수집하고 실패 시 일반 권한으로 대체하지 않는다.
- 실행 계정·UID와 일반 계정의 누락 가능성을 보고서에 기록. root여도 모든 도구·네임스페이스 제한이 해제된다고 보장하지 않는다.
- 로컬 Noto Sans KR·JetBrains Mono, 본문·입력 18px와 표·안내 16px, 더 넓은 입력 폼과 반응형 화면.
- 구현 및 로컬 검증 완료. 실제 SSH·DB 이관·브라우저 검증 결과와 반입 묶음은 [versions.md](versions.md)에 기록한다.

- SSH 키 암호화·호스트 키 확인, Linux 대상 등록·변경, 동시 2개 점검과 최대 16개 대기 작업, 재시작 시 미완료 작업 기록.

- 저장한 스냅샷의 XLSX·ZIP·JSON·요약 MD 다운로드. 웹 XLSX는 취약점 상세를 포함한 31개 시트.
- OSV JSON/ZIP 및 명시적인 CCE/POLICY 규칙 반입. 단일 묶음 검증·트랜잭션 갱신·철회/이전 버전 반입 처리·SHA-256 기록.
- 관리자에서 반입 파일 또는 허용된 내부 HTTPS 미러, 6필드 cron·시간대, 즉시 갱신·성공/실패 이력 관리.
- 초기 목록은 공식 출처 CVE 2건, RHEL CCE 2건, 내부 Docker 정책 1건. 전체 취약점 데이터는 운영자가 반입한다.
- 외부 준비 환경에서 공식 OSV Maven 덤프를 받는 스크립트 제공. 현재 PC의 DB에는 2026-11-11 취득한 Maven 권고 7,257건을 실제 반입해 검증했다. 이 운영 데이터는 Git에 포함하지 않는다.
- CVE 자동 판정은 Maven 좌표/버전의 지원 OSV 범위에 한정한다. CCE는 구현된 설정 키와 OS 적용 기준이 있는 규칙만 실행한다.
- REQ-019: 동일 1.0.0 이미지와 PostgreSQL 18.6, Maven 권고 7,257건·CCE 2건·내부 정책 1건을 Linux amd64 반입 묶음으로 제공한다. 새 관리자/DB 비밀번호·암호화 키를 현장에서 생성하고 기존 운영 DB·접속 정보를 포함하지 않는다. 반입 서버의 Java·Python·OpenSSL 설치는 불필요하다.

REQ-012~018은 위 초기 범위로 수용하며 Windows·다중 앱 인스턴스·전체 생태계 취약점 분석·완전한 SCAP 준수 검증은 포함하지 않는다. 0.2.0의 기본 HTTP 사용 방식이 인증된 웹 플랫폼으로 바뀌므로 대 버전을 올린다. 기존 CLI와 loopback 전용 HTTP collector 프로필은 유지한다.

## 수집 한계와 수용 기준

- 설치된 라이브러리의 존재와 JVM에 실제 로딩된 사실은 구분한다. 버전·라이선스 미확인은 그대로 표시한다.
- 권한, PID/마운트 네임스페이스, attach 비활성화, 누락된 도구에 따른 제한을 기록한다. 모든 계층을 지원하는 방향으로 확장하며 미구현 항목을 완료로 표시하지 않는다.
- JDK 최소 버전 검사, 패키징, JAR 기동, 건강 상태 확인, 명세 생성, 민감정보 제외, 수집 실패 처리를 검증한다.
- 실제 검증 범위와 구현 상태는 `versions.md`에 기록한다.
