# 요구사항

## 목적

서버에서 실행 중인 서비스의 여러 계층을 조사하여 운영자가 검토할 수 있는 명세 문서로 제공한다. Java 소스 정적 분석이 아니라 **실행 환경과 실행 중인 서비스 분석**이 중심이다.

## 확정 요구사항

| ID | 요구사항 |
| --- | --- |
| REQ-001 | Spring Boot, JDK 21.0.13 이상, 단일 실행 JAR |
| REQ-002 | `rules/`의 규칙·요구사항·버전 이력과 대.중.소 버전 관리 |
| REQ-003 | 루트 `resources/` 공유 폴더를 Git 추적에서 제외 |
| REQ-004 | 호스트 OS·자원과 실행 프로세스의 PID·부모·소유자·실행 파일·자원 정보 수집 |
| REQ-005 | Java 프로세스의 JVM 버전·선별 속성·클래스패스와 확인 가능한 라이브러리 이름·버전 수집 |
| REQ-006 | Docker 엔진·컨테이너 이미지·상태·포트·네트워크·마운트와 내부 서비스 프로세스 수집 |
| REQ-007 | 컨테이너와 호스트 PID를 연결하여 컨테이너 내부 Java 서비스도 분석 |
| REQ-008 | 서비스 직군별 분류 및 직군마다 프로세스·오픈소스·컨테이너 명세 분리 |
| REQ-009 | 수집 근거·시각·누락·오류·미지원 범위를 명시하고 일부 실패 시에도 보고서 생성 |
| REQ-010 | 운영 부담을 제한하고 비밀값을 기본 보고서에서 제외 |

## 0.1.0 구현 범위

상태: 초기 구현 및 로컬 검증 완료. 아래 범위에 대한 세부 검증은 [versions.md](versions.md)를 따른다.

- Linux `/proc`와 Java Process API를 통한 프로세스 스냅샷.
- 허용된 `jcmd` 조회 및 실행 JAR/클래스패스의 라이브러리 메타데이터. Spring Boot 중첩 JAR 포함.
- Docker CLI의 조회 명령과 `docker top`을 통한 내부 프로세스 연결. 컨테이너 파일은 접근 가능한 `/proc/<pid>/root`를 통해 조회.
- Markdown 명세 묶음과 JSON 보고서, 로컬 HTTP API와 일회성 보고서 생성 모드.
- 서비스 직군 자동 분류와 설정을 통한 명시적 분류.

REQ-001~003과 REQ-008~010의 초기 수용 기준을 구현했다. REQ-004~007은 아래 후속 확장 항목과 접근 권한에 따른 한계가 남아 있으며 전체 계층의 완전한 분석을 완료한 것으로 보지 않는다.

## 후속 확장 범위

- TCP/UDP 리스닝 포트와 프로세스의 연결, systemd 유닛과 서비스 종속 관계.
- 비 Java 런타임 및 OS 패키지의 상세 버전·라이선스·SBOM, 취약점 정보 연동.
- JVM 동적 클래스 로더와 실제 로딩 라이브러리 증명, JMX 지표, 서비스 호출 관계.
- 원격 서버/원격 Docker, Kubernetes·containerd 등 추가 런타임, HTML/PDF 출력.

## 수집 한계와 수용 기준

- 설치된 라이브러리의 존재와 JVM에 실제 로딩된 사실은 구분한다. 버전·라이선스 미확인은 그대로 표시한다.
- 권한, PID/마운트 네임스페이스, attach 비활성화, 누락된 도구에 따른 제한을 기록한다. 모든 계층을 지원하는 방향으로 확장하며 미구현 항목을 완료로 표시하지 않는다.
- JDK 최소 버전 검사, 패키징, JAR 기동, 건강 상태 확인, 명세 생성, 민감정보 제외, 수집 실패 처리를 검증한다.
- 실제 검증 범위와 구현 상태는 `versions.md`에 기록한다.
