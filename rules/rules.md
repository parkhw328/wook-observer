# 프로젝트 규칙

## 관리 문서

- 개발 지침은 `rules/rules.md`, 요구사항과 구현 상태는 `rules/requirements.md`, 버전 이력은 `rules/versions.md`에서 관리한다.
- 작업 전 세 문서를 읽고 요구사항 변경과 구현 결과를 함께 갱신한다. 사용자 지시가 기존 문서보다 우선한다.
- 사용자와 개발자가 공유하는 루트 `resources/`는 Git에 추가하지 않는다. `git add -f`로도 추가하지 않는다. 애플리케이션 설정용 `src/main/resources/`는 별개이며 추적한다.
- 기존 `AGENTS.md`는 사용자의 보존 지시에 따라 수정하지 않는다. 이후 구체화된 기술·운영 지침은 이 문서와 README를 따른다.

## 기술 및 배포

- 중앙 웹서비스의 구현 언어는 고정하지 않는다. 가용 메모리·CPU·동시 점검·대용량 보고서의 실측과 유지보수 비용을 근거로 Python 등 다른 구현도 선택할 수 있다. 전환 시 API·DB·인증·암호화·보고서·폐쇄망 배포 호환성을 검증한다.
- 현재 구현은 Spring Boot와 Maven Wrapper이며 Java 21 계열의 **21.0.13 이상**을 최소 빌드·실행 기준으로 한다. Java 구현을 유지하는 동안 컴파일 대상은 Java 21이다.
- 중앙 웹서비스는 런타임을 포함한 Docker 이미지와 PostgreSQL로 배포한다. 현재 제공하는 일회성 실행 JAR은 호환성을 유지하며, 런타임 전환 판단은 `docs/runtime-decision.md`에 기록한다.
- 수집기, 데이터 모델, 분류, 보고서 생성을 분리한다. Java 들여쓰기는 4칸, YAML·Markdown은 2칸을 사용한다.
- Linux 호스트에서 실행하는 수집기를 우선 지원한다. 원격 Docker 또는 격리된 PID 네임스페이스를 로컬 호스트로 오인하지 않는다.
- 대상 서버에 Java가 있다고 가정하지 않는다. 중앙 서비스에서 SSH로 Linux 기본 정보를 수집하고 JVM·JAR 상세는 실제 서비스와 도구·권한이 있을 때 추가한다. 도구를 자동 설치하지 않는다.
- 폐쇄망 반입 대상은 Linux x86_64이며 Docker Engine·Compose가 이미 설치되어 있다. 앱·DB 이미지 전체 레이어, 취약점 데이터·출처·해시, 실행 설정과 설치 안내를 함께 제공한다. 반입 후 외부 pull·빌드 없이 시작하고 호스트 Java·Python·OpenSSL을 요구하지 않는다.
- 배포 묶음은 `resources/offline/`에 보관하고 Git에서 제외한다. 기존 `.env`, DB·계정·SSH 키·점검 보고서를 담지 않으며 새 설치의 비밀번호와 암호화 키는 현장에서 생성한다. 외부 통신을 차단한 별도 환경에서 설치·데이터 반영을 검증한다.

## 계정·접속 및 화면

- DB에 사용자, SSH 대상, 점검 이력·스냅샷, CVE/CCE/내부 정책, 갱신 설정·이력을 저장한다. 대상 등록 후 비동기로 점검하고 저장된 결과를 다시 다운로드한다.
- ADMIN은 계정·연결·업데이트를 관리하고 USER는 등록된 전체 대상의 점검·조회 권한을 갖는다. 세션 인증·CSRF 보호·비밀번호 해시를 사용하며 계정 비활성화 및 권한·비밀번호 변경 시 기존 세션을 무효화한다.
- 웹 계정 비밀번호는 8자 이상, UTF-8 72바이트 이하로 검증한다. 최초 관리자·사용자 생성·비밀번호 변경과 화면 안내에 동일하게 적용한다. 계정 편집의 빈 비밀번호는 기존 값 유지이며, 외부 SSH/root 계정의 비밀번호 정책은 대상 서버가 관리한다.
- SSH 개인 키·접속 비밀번호·키 암호·root/sudo 전환 비밀번호는 DB에 암호화하고 API로 반환하지 않는다. 호스트 키는 직접 입력하거나 조회한 지문을 명시적으로 확인해 등록하며 자동 신뢰는 제공하지 않는다.
- 접속 키/비밀번호와 서버 호스트 키의 역할을 구분한다. 일반 계정 점검 또는 선택한 su/sudo root 전환을 지원하고 UID 0을 확인한다. 전환 실패를 일반 권한 점검 성공으로 처리하지 않는다. 비밀번호 값은 명령행·환경변수·로그·보고서에 넣지 않는다.
- 웹은 1.0.0의 일반 고딕체 계열(Inter/Pretendard/Noto Sans KR·시스템 글꼴)로 표시하며 JetBrains Mono를 기본 글꼴로 강제하지 않는다. Noto Sans KR은 로컬 대체 글꼴로 제공한다. 기본 본문·입력 18px, 표·안내 16px의 가독성을 유지하고 모바일·확대 화면을 검증한다. 런타임에 외부 폰트/CDN을 호출하지 않는다.
- 사용자 요청에 따라 자산 관리 화면은 본문·입력 14px, 표 13px, 보조 정보 12px로 밀도를 높이고 본문 최대 폭 제한을 해제한다. 포트는 프로토콜/번호로 요약하고 주소·Docker 매핑을 상세 제공한다. PID는 별도 열에 최대 3개(긴 숫자는 2개)만 표시하고 전체는 마우스오버·키보드 포커스·터치로 조회한다. 내보내기에는 전체 값을 보존한다.
- 포트 출처·미입력 안내와 수정 이력은 마우스오버·키보드 포커스·터치 팝업으로 제공한다. 관측 상태/시각은 유지하고 편집은 별도 최우측 고정 열로 둔다. USER에게는 편집 열을 생성하지 않는다. 왼쪽 메뉴는 16px, 폭 240px(741~1100px에서는 220px)로 본문 공간을 확보하며 모바일 가로 메뉴를 유지한다.
- 네비게이션 상단에는 원형 링 로고와 `Observer`만 한 줄로 표시한다. 로그인과 파비콘에도 같은 SVG를 사용한다.
- 메뉴명은 우측 상단 제목에서 한 번 표시한다. 본문의 중복 메뉴 제목과 WORKSPACE 표기는 제거하고 설명·작업 버튼·실제 서버명과 구역 제목은 유지한다.
- 서비스 목록의 시스템 항목은 기본 표시하고 독립적인 `시스템 서비스 항목 제외` 토글로 숨김/복원한다. 자동 후보의 확인 가능한 OS 프로세스/실행 파일만 판별하며 수동 행·컨테이너·소유자 미확인 소켓을 임의로 제외하지 않는다. 데이터와 XLSX 전체 범위는 유지한다. PID는 천 단위/목록 쉼표 없이 숫자 배지로 표시한다.
- 네비게이션 하단은 `내부망 점검 플랫폼 (버전)` 한 줄만 표시하고 별도 Wook Observer 버전 줄과 메인 화면의 브랜드 푸터를 제거한다.
- 테마는 한화 주황색 계열과 밝은 중립 배경을 참고하되 Wook Observer 고유의 관측 렌즈 로고와 일관된 SVG 탐색 아이콘을 사용한다. 색상·폰트·아이콘은 `docs/interface.md`에서 관리한다.
- 신규 대상은 비밀번호 로그인·호스트 키 자동 조회를 기본으로 한다. 개인 키나 호스트 공개 키를 직접 입력하지 않아도 서버 지문을 확인한 뒤 등록할 수 있어야 한다. 저장된 키 검증과 키 변경 시 접속 차단은 유지한다.
- 현재 중앙 앱은 단일 인스턴스로 운영한다. 다중 인스턴스 작업 큐·클러스터 일정 조정은 별도 구현 없이는 지원으로 표시하지 않는다.

## 취약점 데이터와 판정 원칙

- 폐쇄망에서 외부 접속 없이 기동한다. 반입 JSON/ZIP과 관리자가 허용한 내부 HTTPS 미러로 CVE·CCE 데이터를 갱신한다. 정기 실행은 기본 비활성화한다.
- 이미 배포한 서버용 데이터 단독 반입본은 `resources/catalog/`에 보관하고 Git에서 제외한다. 직접 업로드 파일과 출처·라이선스·해시·안내를 포함한 전달 묶음을 구분한다. 데이터만 갱신할 때 앱 버전·이미지를 변경하지 않으며 취득 시각과 원본 갱신 시각을 따로 기록한다.
- 전체 파일 검증 후 트랜잭션으로 반영한다. 실패 시 기존 데이터를 유지하고 출처·수정/반영 시각·SHA-256·개정 번호·철회 정보를 보존한다.
- 카탈로그는 검색 조건·정렬·페이지·전체 건수를 일관되게 표시한다. 겹친 요청의 오래된 응답이 최신 화면을 덮어쓰지 않게 하고 처음/마지막 페이지·실패 후 재시도를 검증한다.
- CVE는 Maven 패키지 식별자와 버전을 영향 범위에 대조한다. RPM은 RHEL·Rocky·AlmaLinux 8/9/10의 공식 보안 권고에 배포판·공급자·아키텍처·EVR로 대조하며 RHEL은 저장소/CPE·EUS 릴리스 고정을 확인한다. 모듈·스트림 미확인은 미판정이며 소스 RPM 대응은 의심으로만 표시한다. 권고의 upstream/related CVE를 alias로 바꾸지 않는다. 중첩 JAR도 Manifest보다 Maven 메타데이터를 우선하며 묶음 JAR의 여러 좌표를 보존한다.
- Maven 좌표가 없으면 파일명의 정확한 artifactId와 버전으로 내부 카탈로그의 유일한 후보를 찾을 수 있다. 이는 **의심**으로만 표시한다. 이름 유사도·여러 groupId 후보·버전 모순으로 확정 판정하지 않는다.
- 발견 항목은 ID·별칭·패키지·설치 버전·영향 근거·출처·조치 정보를 갖는다. 수정 버전은 해당 영향 구간의 공식 `fixed` 근거가 있을 때만 제시하며 다른 분기 버전을 일괄 권고하지 않는다.
- CCE는 적용 OS가 일치하고 실제 설정 값이 수집되어 기대값에 어긋난 경우만 발견이다. 플랫폼 불일치는 **비대상**, OS/설정/식별 정보 부족과 미지원 범위는 **미판정**이다. CCE와 내부 POLICY를 구별한다.
- **조치 목록과 취약점 건수에는 발견·의심만 포함**한다. 비대상·미판정·미발견을 취약점 행으로 나열하지 않는다. 미판정은 안전 판정이 아니며 이유별 점검 범위 요약과 구조화 근거에 보존한다.
- 같은 CVE/규칙·패키지·버전·서비스 직군의 반복 발견은 하나의 조치로 묶고 영향 PID·컨테이너·경로를 연결한다. 고유 조치 수와 영향 위치 수를 구별한다.

## 운영자 문서와 원본 근거

- SSH가 없는 서버도 파일 업로드 자산으로 등록한다. 고정 SH를 대상에서 실행하고 형식·크기·해시·완료 여부를 검증한 데이터만 반입한다. 서버 신원/수집 시각과 반입 시각을 구별하고 과거 파일로 최신 관측값을 교체하지 않는다. 같은 파일은 중복 저장하지 않으며 검증·판정·저장을 원자적으로 수행한다.
- 전체/개별 자산의 저장된 프로필과 서비스(시스템·보관 포함)를 하나의 Markdown 보고서로 조회/다운로드한다. 실행 절차와 전체 근거를 보존하고 HTML/외부 리소스를 실행하지 않는다.
- 서비스 입력은 넓은 별도 편집 창과 고정 저장/취소 버튼으로 제공하고 모바일/확대·실패 시 입력 보존을 검증한다. 자산의 위치 항목은 서버 위치로 표시한다.
- 등록 자원은 점검 대상이자 관리 자산으로 취급한다. 자산·서비스 운영대장의 수기 정보는 관측 스냅샷과 분리하여 영속 저장하고 재점검으로 덮어쓰지 않는다.
- 서비스명·실행계정·포트·SW/버전·APP/DATA/LOG 경로·담당파트·시작/종료/상태 확인 방법·연계 대상·비고를 관리한다. 상태 확인 명령과 실제 관측 상태, 바인딩 포트와 통신 목적지/방향을 구분한다. 기록한 명령을 실행하지 않는다.
- 서비스 미관측은 중지·삭제·정상으로 추정하지 않는다. 이전 근거·시각과 수기 정보를 보존하며 자산 요약은 대상마다 최근 완료 점검 1회 기준으로 집계한다.
- 제공 Excel은 원본 셀·병합 관계와 열 밀림을 확인해 해석한다. 공통모듈·서비스·포트별 통신 행을 서버 수로 합산하지 않는다. 운영값과 원본 파일은 Git 제외 resources에 둔다.

- 분석 범위는 호스트 → 프로세스 → 런타임/JVM → 라이브러리, Docker → 컨테이너 → 내부 서비스의 연결 관계다. 애플리케이션·웹·DB·캐시·메시징·인프라·기타 직군을 구분하고 자동 분류 근거를 보존한다.
- 기본 화면·요약은 **관측 대상과 시각 → 발견·의심 조치 → 점검 범위 요약 → 명세 링크** 순서로 구성한다. 동일한 경고·범위 문구를 각 행마다 반복하지 않는다.
- 직군별 프로세스·오픈소스·컨테이너 명세는 유지한다. 빈 직군은 운영 화면/Excel에서 숨기고, 동일 이름·버전 라이브러리는 한 행으로 묶어 영향 위치를 연결한다. 원래 위치·버전·식별 근거는 잃지 않는다.
- Markdown·JSON·XLSX는 동일한 저장 스냅샷을 사용한다. `report.xlsx`의 첫 시트는 요약·조치·점검 범위이며 명세와 원문은 부록으로 분리한다. 원문 시트는 기본 접어두되 복원 방법과 이동 링크를 제공한다.
- 파일별 Markdown과 구조화 JSON 원문을 XLSX에 함께 보존한다. 필터·고정 헤더·내부 링크를 제공하고 긴 원문은 셀 제한에 맞춰 분할한다. 수집 문자열을 수식으로 실행하지 않는다.
- 이전 JSON 스냅샷은 읽기 호환성을 유지한다. 표시를 정리할 수는 있지만 다운로드할 때 최신 카탈로그로 재판정하거나 저장된 판정·개정·원본을 덮어쓰지 않는다. 수집/판정 개선은 새 점검부터 반영된다.
- 라이브러리 존재, 실제 로딩, 오픈소스 여부, 라이선스, 악용 가능성을 구분한다. 미확인 정보와 파일명 추정을 사실로 확정하지 않는다.
- OS 배포판과 실행 커널을 구분하고 `uname -a/-r/-v/-m`, `/etc/os-release`, `/etc/redhat-release`, `/proc/version`을 근거와 함께 남긴다. 릴리스 파일을 셸 코드로 실행하지 않는다.
- 설치 RPM은 이름·Epoch·버전·Release·아키텍처를 보존한다. 호스트 설치 목록을 서비스 사용이나 취약점으로 추정하지 않는다. 소스 RPM·모듈·공급자·저장소 ID를 보존하되 저장소 URL·자격 증명은 수집하지 않는다.
- 열린 포트는 `ss`의 TCP 리스닝·전체 UDP 바인딩을 프로토콜별 5초·4,096개·512 KiB 이내 수집한다. IPv4/IPv6·PID/프로세스·실패 상태를 보존하며 외부 도달 가능성으로 해석하지 않는다.
- 수집 시각·실패·도구 없음·권한 부족·시간/용량 제한을 보존하되 같은 오류는 대상 목록과 함께 묶는다. 수집 실패를 빈 결과나 정상 분석으로 표시하지 않는다.

## 운영 및 검증

- 기본 INFO 운영 로그에 요청/점검/대상 ID·수행자·단계·건수·시간·실패 종류를 기록한다. 일반 조회와 메시지를 제외한 예외 코드 위치는 DEBUG에서 제공하며 비동기 작업으로 추적 문맥을 전달하고 재사용 스레드에서 정리한다. 비밀번호·키·토큰·본문·쿼리·명령·수집 원문·예외 메시지는 로그에 넣지 않는다. Compose 로그 크기를 제한하고 운영 안내를 동봉한다.
- 기본 수집은 읽기 중심이다. 프로세스 종료, 컨테이너 변경, 임의 명령 실행, 힙 덤프, 강제 GC, 에이전트 주입을 수행하지 않는다.
- 환경변수 값, 전체 명령행, 임의 JVM 시스템 속성을 보고서에 노출하지 않는다. 필요한 메타데이터를 선별한다.
- 명령 실행 시간과 수집량을 제한하고 일부 수집 실패가 전체 문서 생성을 막지 않게 한다.
- 테스트는 JUnit 기반으로 작성한다. Docker·JVM 경계는 고정 fixture로 검증하고 실제 환경 검증 결과와 구별한다.
- 커밋은 `feat:`, `fix:`, `docs:`, `test:`, `chore:`와 명령형 요약을 사용한다. PR에는 변경 목적·검증·미지원 범위를 적는다.

## 버전 정책

- `대.중.소`의 세 정수 형식과 Git 태그 `v대.중.소`를 사용한다.
- 대: 호환성을 깨는 변경. 중: 호환성을 유지하는 기능 추가. 소: 버그 수정·문서·빌드 개선.
- 대 또는 중 버전을 올리면 하위 숫자는 0으로 초기화한다. `pom.xml`, 배포 JAR, 버전 이력의 버전을 일치시킨다.
- `0.0.0`은 프로젝트 시작 기준이며 첫 동작 가능한 수집·보고서 버전은 `0.1.0`으로 관리한다.
- 이미 배포된 바이너리를 그대로 반입 묶음으로 포장할 때는 앱 버전과 기존 Git 태그를 유지한다. 포장 변경은 manifest의 `bundleRevision`·생성 시각·SHA-256과 버전 이력에 별도로 기록하며 기존 릴리스 태그를 이동하지 않는다.
