# 운영자 보고서 읽기

## 먼저 확인할 내용

1. 요약의 대상·관측 범위·시각과 카탈로그 개정을 확인합니다.
2. 발견·의심 조치를 확인하고 패키지·설치 버전·영향 PID/컨테이너/경로를 연결합니다.
3. 의심 항목은 Maven 좌표를 확인합니다. 수정 경계는 해당 권고의 영향 구간 기준이며 모든 CVE에 대한 안전 버전을 뜻하지 않습니다.
4. 점검 범위에서 미판정 원인을 확인합니다. 필요한 메타데이터·권한·도구·취약점 자료를 보완한 뒤 새 점검을 실행합니다.

## 판정과 집계

| 상태 | 의미 | 조치 목록 |
| --- | --- | --- |
| 발견 | Maven 메타데이터의 버전이 영향 범위에 포함되거나 적용 OS의 설정이 기준에 어긋남 | 포함 |
| 의심 | 파일명/메타데이터로 찾은 Maven 후보 버전이 영향 범위에 포함됨 | 포함, 좌표 확인 필요 |
| 미발견 | 수집한 식별 정보로 지원하는 등록 기준을 대조했으나 일치 없음 | 제외 |
| 비대상 | 알려진 OS가 CCE 적용 OS와 다름 | 제외 |
| 미판정 | 좌표·버전·기준·설정 부족, 여러 후보, 미지원 범위 등 | 제외, 안전 판정 아님 |

조치는 ID·서비스 직군·패키지·버전·발견/의심 상태를 기준으로 묶습니다. 동일 JAR가 두 JVM에서 발견되어도 한 조치와 두 영향 위치로 표시합니다. 다른 버전/직군은 합치지 않습니다. 별칭과 각 출처·근거·조치는 보존합니다.

점검 범위의 CVE 수는 라이브러리 위치, CCE/POLICY 수는 대상별 규칙입니다. 일부 권고만 미지원인 라이브러리는 발견과 미판정에 모두 포함될 수 있어 상태 수를 단순 합산하지 않습니다. 라이브러리 명세는 직군·패키지·버전별로 묶습니다. 파일명 후보는 신원 확정이 아닙니다.

예를 들어 RHEL 9 CCE 규칙으로 Ubuntu를 점검하면 비대상입니다. RHEL 9에서 값이 미수집이면 미판정이며, 값이 수집되어 기대값과 다를 때만 발견입니다. 파일명만 같은 여러 Maven groupId는 임의로 하나를 선택하지 않습니다.

## 파일과 화면

- 웹 상세: 조치·점검 범위 우선, 라이브러리·OS/RPM·수집 제한은 펼쳐 보기. 조치/라이브러리는 첫 200개이며 전체는 다운로드합니다.
- `summary.md`: 간략 현황과 명세 링크. `actions.md`: 발견·의심 상세. `coverage.md`: 점검 범위와 반복을 줄인 수집 오류.
- `services/<직군>/`: 프로세스·오픈소스·컨테이너 명세. 기존 경로를 유지하고 요약에서는 빈 직군을 생략합니다.
- `report.xlsx`: 앞 시트는 요약·조치·점검 범위. 빈 명세와 원문 시트는 숨김입니다. 시트 탭 우클릭 → 숨기기 취소로 열 수 있습니다. 원문 목록의 SHA-256과 조각 순서로 MD/JSON을 복원합니다.
- `report.json`: 위치별 원본 명세, 조치 근거인 `assessment.findings`, 판정 범위인 `assessment.coverage`. 원본 위치와 식별 근거는 삭제하지 않습니다.

## 이전 버전과 수집 제한

기존 DB·계정·대상·스냅샷은 유지합니다. 과거 보고서도 조치 중심으로 표시하지만 당시 판정과 개정을 재계산하지 않습니다. 1.3 이하의 누락된 좌표는 **새 점검**부터 보완됩니다. 이전 점검 이력의 저장 건수는 당시의 위치별 건수이며 새 점검부터 중복 제거한 조치 수입니다.

대상에 Java/Python을 자동 설치하지 않습니다. Linux 기본 수집은 둘 다 없어도 가능하며 SSH의 JAR 내부 메타데이터는 대상의 Python 3가 있어야 읽습니다. 도구·권한 부족은 점검 범위로 표시합니다. 로컬 JAR 수집은 Java 런타임으로 JAR를 읽습니다. 실제 클래스 로딩·악용 가능성, OS/RPM 및 비 Java CVE 대조는 이번 범위에 포함되지 않습니다.

## 검증 명령

```bash
./mvnw verify
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s src/test/python
```

개발 PC에 Playwright/Chromium을 준비한 경우 `scripts/check-operator-ui.py --url <시험 서비스> --env-file <시험 자격증명 파일> --job <합성 점검 ID> --output resources/ui-check`로 페이지 경합·재시도·모바일 표시를 검증할 수 있습니다. 공개 Maven 목록과 합성 CVE-2021-44228 점검 fixture가 있는 격리 시험 배포를 사용합니다.

카탈로그 API `/api/catalog/page?query=...&page=0`은 0부터 시작하는 페이지, 50개 항목, 전체 건수·페이지 수·이전/다음 여부를 제공합니다. 기존 `/api/catalog` 목록 API도 유지합니다. 화면은 렌더 요청 번호로 오래된 응답을 무시합니다.
