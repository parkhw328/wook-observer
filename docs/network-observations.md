# 네트워크 관측과 필터

## 수집 범위

1.12.0은 같은 로컬 네트워크 네임스페이스에서 다음을 각각 조회한다. 대상에 도구를 설치하거나 외부로 접속하지 않는다.

| 범위 | 우선 명령 | ss가 없을 때 | 한도 |
| --- | --- | --- | --- |
| TCP LISTEN | `ss -lntp` | `netstat -lntp` | UDP와 합해 4,096개·512 KiB |
| UDP 바인딩 | `ss -naup` | `netstat -anup` | TCP LISTEN과 합산 |
| TCP 연결/종료 대기 | `ss -antp` 결과 중 LISTEN 제외 | `netstat -antp` 결과 중 LISTEN 제외 | 별도 4,096개·512 KiB |

명령별 5초 제한(강제 종료 유예 2초)을 사용한다. 연결이 많아도 바인딩 수집 한도를 사용하지 않는다. ESTABLISHED 외 TIME_WAIT·CLOSE_WAIT·SYN_SENT 등 관측된 상태를 보존하며 `ESTAB/ESTABLISHED`, `CLOSE-WAIT/CLOSE_WAIT` 등의 도구 차이는 통일한다. 현재 도구가 표시하지 않는 비활성 TCP 바인딩은 지원 범위가 아니다.

로컬·상대 주소/포트, 상태, 도구, 확인 가능한 PID/프로세스를 보존한다. 같은 주소·포트의 연결을 임의로 합치지 않는다. PID가 없다는 이유로 커널 소켓이라고 단정하지 않는다. 권한 부족, 종료된 프로세스, TIME_WAIT 등의 경우 소유자가 미확인일 수 있다. IPv6/영역 ID도 보존한다. 호스트에서 보이지 않는 다른 컨테이너 네임스페이스 내부 전체 연결은 수집하지 않는다.

바인딩과 연결은 별도 시점의 조회이며, 연결은 단일 스냅샷이다. 연결 시도 주체/인바운드·아웃바운드 방향, 실제 트래픽 양, 포트 외부 도달 가능성을 판정하지 않는다. 패킷 내용·전체 명령행·환경변수를 수집하지 않으며 숫자 주소/포트로 조회해 이름 해석을 하지 않는다.

## 필터의 의미

- **전체 / TCP LISTEN / TCP ESTABLISHED / 기타 TCP 상태 / UDP**: 관측된 상태에 따라 표시한다.
- **시스템 서비스 제외**: 확인 가능한 OS 프로세스 이름/실행 파일에 해당하는 후보를 숨긴다. 모든 소유자가 시스템 후보일 때만 해당하며 컨테이너·소유자 미확인은 임의로 제외하지 않는다. root 계정이나 낮은 포트 번호만으로 판별하지 않는다.
- **예약 포트 제외**: 서버의 `/proc/sys/net/ipv4/ip_local_reserved_ports`에 포함된 **로컬** 포트를 숨긴다. 이 설정은 자동 포트 할당에서 제외할 목록이며 OS 전용 서비스 목록이 아니다. 빈 목록을 수집한 경우와 조회 실패를 구별한다.
- **자동 할당 범위 제외**: `/proc/sys/net/ipv4/ip_local_port_range` 안의 **로컬** 포트를 숨긴다. 해당 범위에도 명시적으로 바인딩한 업무 서비스가 있을 수 있어 실제 임시 포트 사용을 확정하지 않는다.

두 설정을 각각 최대 4 KiB·2초로 읽고 값·출처·상태를 남긴다. 설정을 변경하지 않으며 미수집/실패 시 포트 범위를 추정하지 않는다. 예약/자동 할당 범위는 독립적이므로 둘에 동시에 속할 수 있다. 기본은 전체 표시이고 필터는 서로 조합할 수 있다. 미확인 근거를 가진 행은 근거 없이 숨기지 않는다. 주소·포트·프로세스·전체 PID 검색과 50행 단위 페이지를 제공한다.

## 저장과 내보내기

연결 목록은 점검 스냅샷의 `systemInventory.connections`, 포트 설정은 `systemInventory.networkSettings`에 저장한다. 기존 바인딩은 `sockets`에 유지하고 상대 주소/포트·도구 필드를 추가했다. 자산은 최근 관측 스냅샷의 연결을 표시한다. 연결의 임시 포트나 상대 서버 변화가 서비스 후보 식별 키에 영향을 주지 않으며 수기 운영대장을 덮어쓰지 않는다.

자산·업로드 미리보기·점검 상세의 접을 수 있는 **네트워크 관측**을 연다. MD와 JSON은 전체 근거를 보존하며, 자산 XLSX에는 **네트워크 관측 / 네트워크 수집 범위** 두 시트를 추가한다. 점검 XLSX의 기존 **열린 포트** 시트도 연결과 상대 주소·분류·도구로 확장한다. 화면 필터/페이지/서비스 숨김과 관계없이 수집된 전체를 내보낸다. 제한에 걸린 수집을 실제 전체 연결로 해석하지 않는다.

## 이전 버전과 오류

앱을 1.12.0으로 업데이트한 뒤 같은 버전 SH로 재수집한다. 기존 `.observer`와 DB 스냅샷은 읽을 수 있지만 TCP 연결·상대 주소·포트 정책은 **미수집/미확인**이다. 없는 데이터를 연결 없음으로 표시하거나 과거 보고서를 재판정하지 않는다. 원본 DB 보고서는 수정하지 않으며 새 API 응답에는 누락된 새 항목의 미수집 상태가 추가된다. 네트워크 근거는 기존 보고서 JSON에 보존한다. 같은 버전의 V6 마이그레이션은 별도 수기 정보인 ELS 계약 필드를 자산 프로필에 추가한다.

새 SH 결과의 `CONNECTION`·`CONNECTION_STATUS`·`NET_SETTING` 레코드는 1.12.0 앱에서 반입한다. 해시·UTF-8·완료·크기·건수 제한 검증은 유지한다. 도구 없음/실패/시간 초과/부분 수집은 바인딩과 연결 각각 표시하고 유효하게 수집한 다른 자산 근거를 보존한다. 새 SH가 만든 파일을 이전 앱에 올리면 알 수 없는 레코드로 거부될 수 있다.

CentOS 7.9의 ss와 net-tools 기반 netstat에서 실제 IPv4/IPv6 ESTABLISHED·CLOSE_WAIT·FIN_WAIT2와 UDP, 격리된 커널 포트 설정을 검증했다. 컨테이너는 시험 호스트 커널을 공유하므로 물리 EL7의 모든 커널·권한 조합을 검증했다는 뜻은 아니다.

## 공식 근거

- [iproute2 ss 매뉴얼](https://man7.org/linux/man-pages/man8/ss.8.html): 소켓 조회 옵션과 상태.
- [net-tools netstat 매뉴얼](https://man7.org/linux/man-pages/man8/netstat.8.html): 숫자 주소·전체/리스닝 조회와 프로세스 표시.
- [Linux 커널 IP sysctl 문서](https://docs.kernel.org/networking/ip-sysctl.html): `ip_local_port_range`와 `ip_local_reserved_ports`의 독립성과 자동 할당 동작.
