# SSH 접속과 점검 권한

## 대상 등록

관리자의 **점검 대상 → 대상 등록 / 연결 설정**에서 서버 주소·포트·접속 계정을 입력합니다. 대상에 Java나 수집 에이전트를 설치하지 않습니다.

| 구분 | 선택 방법 |
| --- | --- |
| 서버 신원 확인 | 기본: 저장 시 지문 자동 조회·확인. 선택 설정에서 공개 키 직접 입력 가능 |
| SSH 로그인 | 기본: SSH 계정 비밀번호. SSH 개인 키 방식도 선택 가능 |
| 점검 권한 | 접속 계정 그대로, `su`로 root 전환, 비밀번호 `sudo`, 비밀번호 없는 `sudo` |

비밀번호 방식은 개인 키나 공개 키를 직접 입력하지 않아도 됩니다. **연결 정보 저장**을 누르면 서버 지문을 조회하고, 관리자가 확인한 값과 대조한 뒤 확인 체크와 **지문 확인 후 저장**을 누르면 등록됩니다. 필요하면 **서버 지문 미리 조회**로 먼저 확인할 수 있습니다.

호스트 공개 키는 **서버의 신원**, SSH 개인 키·비밀번호는 **로그인 계정**을 확인합니다. 조회한 서버 키는 앱이 저장하므로 비밀번호 접속에서도 같은 서버인지 검증합니다. 기존 대상은 저장된 키와 지문을 유지하고 주소·포트·조회 키를 바꾸면 확인을 다시 해야 합니다. 키가 바뀐 서버에 비밀번호를 보내거나 검증을 건너뛰지 않습니다.

서버 관리자는 대상에서 다음 명령으로 지문을 확인할 수 있습니다.

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

직접 입력에는 `.pub` 또는 `known_hosts`의 한 줄을 사용할 수 있고 마지막 주석도 허용합니다. Ed25519·RSA·ECDSA 공개 키를 지원하며 다른 서버 키나 변경된 키는 접속 단계에서 거부합니다. 조회만으로 신원을 자동 신뢰하지 않습니다. [OpenSSH 호스트 키 조회 설명](https://man.openbsd.org/ssh-keyscan.1)

## 일반 계정에서 root로 점검

- **접속 계정 권한**: 일반 계정은 접근 가능한 범위를 수집합니다. SSH 접속 계정 자체가 root라면 별도 전환이 필요 없습니다.
- **root 비밀번호로 전환 · su**: 일반 계정으로 SSH 로그인한 뒤 root 계정 비밀번호로 `su`를 실행합니다. 대상의 root 계정과 해당 사용자의 PAM/su 정책이 이를 허용해야 합니다.
- **sudo 인증 비밀번호**: 대상의 sudo 정책에 맞는 비밀번호를 입력합니다. 보통 SSH 접속 계정의 비밀번호이며 root 비밀번호와 다를 수 있습니다.
- **비밀번호 없는 sudo**: 해당 계정에 필요한 NOPASSWD 권한이 이미 설정된 경우 사용합니다.

권한 전환은 고정된 읽기 중심 수집 스크립트에만 적용합니다. 임의 명령 입력이나 대상의 sudoers·PAM·SSH 설정 변경 기능은 제공하지 않습니다. sudo의 TTY 요구를 지원하도록 전환 과정에서 SSH 터미널을 할당하고 비밀번호 에코를 끕니다. 실제 UID 0을 확인한 뒤 수집하며 실패하면 일반 권한으로 대체하지 않고 점검 실패로 기록합니다.

보고서의 관측 범위에 실행 계정과 UID를 표시합니다. root여도 컨테이너 네임스페이스, attach 제한, 누락된 Docker CLI·Python·jcmd, 지원하지 않는 런타임 때문에 일부 항목을 수집하지 못할 수 있습니다. 누락 사유는 보고서에서 확인하세요.

## 저장과 변경

개인 키·SSH 비밀번호·개인 키 암호·권한 전환 비밀번호는 DB에 AES-256-GCM으로 암호화합니다. 조회 API와 화면에 비밀값을 반환하지 않습니다. 같은 인증/전환 방식을 편집할 때 빈 비밀번호는 기존 값을 보존하고, 방식을 바꾸면 사용하지 않는 비밀값을 지웁니다. 개인 키를 교체하면 필요한 키 암호도 다시 입력하세요.

비밀번호 값은 명령행 인수나 환경변수에 넣지 않습니다. 중앙 앱의 OpenSSH 입력 도구가 권한 600의 임시 파일을 읽고 작업 종료 시 파일을 삭제합니다. Docker 배포에서는 해당 파일이 `/tmp` tmpfs에 생성됩니다. root/sudo 비밀번호는 에코가 꺼진 인증 프롬프트에 한 번만 전달합니다. [OpenSSH 비밀번호 입력 환경](https://man.openbsd.org/ssh.1)

Docker 이미지에는 `scripts/ssh-askpass.sh`가 포함됩니다. 중앙 웹 JAR를 Docker 밖에서 실행할 때는 OpenSSH 클라이언트와 이 실행 가능한 스크립트를 준비하고, 필요하면 `--observer.platform.ssh-askpass=/절대경로/ssh-askpass.sh`를 지정하세요. **대상 서버**에는 이 스크립트가 필요하지 않습니다.

현재 로그인은 OpenSSH 공개 키 또는 SSH password 인증입니다. keyboard-interactive·OTP·다단계 PAM 대화와 SSH bastion/ProxyJump는 지원하지 않습니다. 호스트 키 조회는 최대 2개 동시 실행·12초, root 전환 응답은 30초, 전체 점검은 180초로 제한합니다.
