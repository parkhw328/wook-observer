# 중앙 서비스 런타임 선택

## 현재 결정 — 2026-11-11 / 1.2.0

웹서비스의 구현 언어는 필수 요구사항이 아니다. Python 등으로 전환할 수 있으며 자원 실측과 호환성·유지보수 비용으로 판단한다. 이번 버전은 Spring Boot를 유지한다. 대상 Linux 서버의 OS·RPM·프로세스 기본 수집에는 Java나 Python이 필요하지 않으며, 중앙 Docker 이미지가 자신의 Java 런타임을 포함한다.

실행 중인 1.1.0의 유휴 상태를 `docker stats --no-stream`으로 한 번 측정했다.

| 대상 | 메모리 사용 / 제한 | CPU |
| --- | --- | --- |
| 앱 | 352.4 MiB / 2 GiB | 0.03% |
| PostgreSQL | 67.14 MiB / 1 GiB | 0.01% |

호스트의 가용 메모리는 약 30.4 GiB였다. 이 값은 특정 PC의 유휴 시점 관측이며, 최소 사양·최대 사용량·장기 안정성 검증이 아니다. 현재 측정에는 즉시 재작성해야 할 자원 부족 징후가 없다. Python 구현의 비교 측정은 하지 않았으므로 더 가볍다고 단정하지 않는다.

1.2.0의 별도 시험 앱에서 RPM 155건인 Rocky Linux SSH 점검 2회와 MD/JSON/XLSX/ZIP 다운로드를 순차 실행했다. 약 2초 간격의 앱 표본 2개는 메모리 368.1~433.6 MiB, CPU 8.77~65.76%였다. 작은 fixture 검증이며 동시 점검·최대 수집량·카탈로그 갱신을 포함한 부하 시험이 아니므로 운영 최대치로 해석하지 않는다.

## 전환을 다시 검토할 조건

- 실제 배포 서버의 메모리·CPU 예산에서 동시 2개 점검, 최대 RPM/라이브러리 결과, XLSX/ZIP 생성, 취약점 데이터 갱신을 실행해 최고 메모리·CPU·소요 시간·OOM/오류를 확인한다.
- 먼저 동시성·작업 상한·JVM 메모리 설정·보고서 생성 경로를 조정하고, 요구 예산을 맞추기 어려우면 같은 데이터로 Python 등의 작은 대조 구현을 측정한다. 언어 이름만으로 자원량을 예측하지 않는다.
- 전환 범위는 중앙 API·작업 실행기·보고서 생성기를 구분한다. 이번에 분리한 셸 수집 프로토콜과 JSON 스냅샷은 재사용 가능하다.
- PostgreSQL 데이터·스냅샷, 암호화된 SSH 자격 증명, 로그인/CSRF·권한·세션 무효화, 호스트 키·su/sudo 동작, 취약점 범위 판정, XLSX 원문 보존, 폐쇄망 이미지의 회귀 시험을 통과해야 한다.
- 기존 일회성 JAR은 독립 도구로 유지할 수 있다. 교체가 필요하면 대체 실행 방법·마이그레이션·복구 경로를 먼저 제공한다.

작업 부하를 측정할 때는 대상 규모·동시성·컨테이너 메모리 제한·버전·샘플 간격을 함께 기록한다. 평소 사용량 하나를 운영 최대치로 사용하지 않는다.
