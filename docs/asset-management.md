# 자산 대시보드와 서비스 운영대장

## 기준 자료와 해석

사용자가 제공한 `resources/wPost-body-2026-11-16.xlsx`를 2026-11-16에 읽어 화면과 데이터 구조를 정의했다. 원본은 변경하지 않으며 운영 서버명·IP·경로·명령을 소스나 시험 데이터에 복사하지 않는다. 원본과 분석 결과는 Git 제외 `resources/`에 둔다.

| 시트 | 헤더 제외 물리 행 | 열 | 명시된 HOST명·IP 조합 | 의미 |
| --- | ---: | ---: | ---: | --- |
| 1단계 | 17 | 16 | 17 | 서버 및 기반 서비스·운영 절차 |
| 2단계 | 15 | 15 | 6 | 한 서버의 여러 업무 애플리케이션과 담당파트·APP/DATA/LOG |
| 병합 | 60 | 15 | 20 | 공통모듈, 서버별 서비스, 포트별 연계 정보를 합친 운영대장 |

첫 두 시트의 서버 조합 합집합은 17개이고 병합 시트에 3개가 추가되어 전체 20개다. 동일 서버의 여러 행을 별도 서버로 집계하지 않는다. `병합!A2:D7`은 공통모듈 구역이며 서버가 아니다. `병합!17:36`은 동일 서비스에 연결된 통신 경로 20행이다. 공통모듈 6행과 연계 연속행 19행을 분리하면 서버·서비스 행 묶음은 35개다. 다중 서비스명이 포함된 묶음도 있으므로 **35개를 확정된 서비스 수로 사용하지 않는다.**

## 가져오기 전 확인할 내용

- `병합!F11:F13`, `F15:F16` 등 13개 셀에는 버전 대신 담당파트에 해당하는 값이 있다. `버전`과 `담당파트`를 분리해야 한다.
- `병합!I11:I13` 등 12개 셀에는 설치위치 대신 실행계정이 있다. `L11:L13` 등 13개 셀에는 서비스시작 대신 로그 경로가 있다. 일부 행은 이후 시작·종료 명령까지 밀려 있다. 헤더만으로 일괄 반입하면 명령의 용도가 뒤바뀐다.
- `병합!K41`은 포트가 아니라 DATA 경로다. `2단계!H2:H16`의 서비스포트는 모두 빈 값이며 포트 0개를 의미하지 않는다.
- `서비스상태`와 `상태` 열은 실행 상태 값이 아니라 **상태 확인 방법**이다. 수집 시점의 관측 상태와 별도 필드로 관리한다.
- 서비스포트에는 단일 포트, 여러 포트, 범위, 출발·목적지와 방향이 섞여 있다. 실제 바인딩 소켓과 연계 대상·통신 방향을 구분한다. Docker의 선언 포트도 호스트 바인딩과 동일시하지 않는다.
- `1단계!N3`, `병합!M47`의 명령 철자와 `2단계!O2`, `O8`의 유니코드 대시 등은 운영자 확인 대상이다. 원문을 자동 수정하거나 실행하지 않는다.
- 병합 셀 값은 해당 병합 범위 안에서만 상속할 수 있다. 빈 행·셀 전체에 앞 행 값을 일괄 채우면 다른 서비스의 계정·명령이 섞일 수 있다. 시트 간 중복을 합산하거나 공통모듈을 모든 서버에 설치된 것으로 추정하지 않는다.
- 자료의 RHEL 7.9 및 Windows Server 2019는 현재 RPM 판정 지원 범위(RHEL 계열 8/9/10) 또는 Linux SSH 수집 범위와 다르다. 자산에 작성된 정보와 실제 수집·판정 지원 여부를 구분해야 한다.

이 때문에 이번 구현은 엑셀 구조를 화면에 반영하며 원본 내용을 DB에 자동 반입하지 않는다. 후속 반입 기능은 **시트·원본 셀 보존 → 컬럼 대응 → 병합/중복/밀린 행 검토 → 미리보기 → 선택 반영** 순서가 필요하다.

## 컬럼 대응과 자동 채움 범위

| 엑셀 항목 | 화면 / 저장 단위 | 자동 채움 |
| --- | --- | --- |
| HOST명, IP, 항목/서버명, O/S | 서버 자산, 연결 주소, 수집 호스트·OS | 등록 정보 및 최근 완료 점검 |
| 구분, SW, 버전 | 서비스 종류, SW, SW 버전 | 수기. 이미지와 JVM 버전을 제품 버전으로 추정하지 않음 |
| 서비스명, 어플리케이션명 | 서비스 표시 이름 | 프로세스·컨테이너 이름 후보 제공, 수기 보완 |
| 담당파트 | 서비스 담당파트 / 담당자 | 수기 |
| 실행계정 | 서비스 실행계정 | PID에서 확인된 계정, 수기 보완 |
| 설치위치, APP | APP / 설치위치 | 수기. 실행 파일 경로는 별도 관측 근거로 제공 |
| DATA, LOG, 로그위치 | 데이터·로그 경로 | 수기, 여러 경로/줄바꿈 보존 |
| 서비스포트 | 자동 관측 바인딩 + 운영 포트/보완 | TCP/UDP 주소·포트·PID, Docker 선언/매핑 |
| 서비스시작/시작, 서비스종료/중지 | 시작·종료 방법 | 수기, 여러 줄과 명령 순서 보존 |
| 서비스상태/상태 | 상태 확인 방법 | 수기, 실행 상태와 분리 |
| 목적지·통신방향 | 연계 대상 / 방향 | 수기 텍스트. 실제 통신 성공·방화벽 허용으로 해석하지 않음 |
| 비고 | 서비스 메모 | 수기 |

추가 자산 필드는 자산번호, 환경, 담당자, 서버 위치, 서버 용도, 운영 상태, 메모다. 등록 자산에 속한 서비스는 미들웨어·애플리케이션·공통/보안/백업·미분류로 관리한다. 공통 서비스는 현재 서버마다 수동 등록할 수 있다.

## 사용 흐름

1. **대시보드**에서 등록 자산, 서비스 후보·등록 수, 절차 보완 수, 자산별 최근 발견·의심을 확인한다. 발견·의심은 각 자산의 최근 완료 점검 1회만 합산한다.
2. **자산 관리**에서 서버·주소·자산번호·담당·위치·용도로 검색하고 환경, 점검 전, 절차 보완, 최근 실패로 필터링한다.
3. 자산을 열어 담당자·환경·용도 등 자산 정보를 저장한다.
4. 서비스 운영대장에서 자동 후보를 편집하거나 **수동 서비스**를 추가한다. 시작·종료·상태 확인 방법, 경로, 담당파트, 연계 정보를 넓은 편집 창에서 입력하고 서비스 단위로 저장한다. 관리 종료 항목은 보관하고 보관함에서 다시 편집해 복원한다.
5. 최근 점검을 열어 당시의 보고서와 판정을 확인한다. 수정한 운영대장이 과거 보고서를 변경하지 않는다.
6. 목록의 **전체 자산 XLSX** 또는 서버 상세의 **자산 XLSX**로 저장된 운영대장을 내려받는다.

ADMIN은 자산·서비스를 편집하고 USER는 조회·점검한다. 저장은 서버 DB에 반영되며 수정자·수정 시각·개정 번호를 남긴다. 동시 수정은 HTTP 409로 차단하고 작성한 내용을 화면에 남긴다. 운영 절차는 기록용 텍스트이며 원격 실행 API나 버튼을 제공하지 않는다. 자격 증명은 운영 메모 대신 기존 연결 설정에서 관리한다.

## 1.10.0 편집과 Markdown 보고서

서비스 편집은 좁은 표 셀 대신 최대 1,440px의 창을 사용한다. 기본 정보·경로와 포트·시작/종료/상태 확인 절차·연계와 메모를 나누고, 하단 저장/취소 버튼을 항상 표시한다. 화면이 좁으면 한 열로 배치하며 textarea를 세로로 늘릴 수 있다. 저장 실패/충돌 시 입력을 보존하고, 수정한 내용이 있을 때 창 닫기·Escape·이동 시 폐기를 확인한다. 자산 프로필은 넓은 다열 입력과 메모 공간을 제공하며 `location`의 표시 이름은 **서버 위치**다. 기존 값은 그대로 보존한다.

목록의 **전체 자산 MD 보고서**, 서버 상세의 **자산 MD 보고서**는 현재 저장된 프로필과 모든 서비스(시스템·보관 포함)를 일관된 DB 읽기로 생성한다. 자산 목록, 서버 위치/용도/담당, 최근 수집 기준·제한, 서비스별 SW/경로/전체 포트·PID·실행 절차를 단일 Markdown으로 구성한다. 화면에 표시된 문서를 그대로 다운로드하므로 열람과 저장 사이의 데이터 변경에 영향을 받지 않는다. 새로고침하면 현재 저장 내용으로 다시 만든다. HTML·외부 이미지·스크립트는 실행하지 않고 데이터로 표시한다. SSH 자격 증명은 포함하지 않는다.

직접 연결할 수 없는 서버는 [현장 수집과 업로드](offline-collection.md)로 등록한다. SSH 등록/수기 정보와 파일 업로드 관측을 함께 사용할 수 있으며, 현재 관측값은 업로드 순서가 아니라 실제 수집 시각을 기준으로 한다.

## 1.7.0 표와 XLSX

자산 목록·상세는 사용 가능한 본문 가로 폭을 모두 사용한다. 표 글자는 13px, 보조 정보는 12px이며 패널 여백과 행 간격을 줄였다. 운영 절차 보기는 최소 1,040px, 전체 항목은 1,560px이며 별도 PID·편집 열을 포함한다. 작은 화면에서는 표 안에서 스크롤한다.

- `TCP 0.0.0.0:443`과 `TCP [::]:443`은 **TCP 443** 하나로 묶는다. TCP/UDP는 구분하며 최대 4개 요약과 나머지 개수를 표시한다.
- **바인딩 포트 값**에 마우스를 올리거나 포커스/클릭하면 모든 주소와 자동 관측·운영 포트 보완 정보를 확인한다. 포트 값이 없는 `—`도 같은 방식으로 미입력/미확인 이유를 보여준다. Docker는 호스트 포트 → 컨테이너 포트를 표시하고 내부 선언과 구분한다. 알 수 없는 형식도 상세에 원문을 남긴다. 화면 요약은 저장된 원문·서비스 식별을 변경하지 않는다.
- PID는 별도 열에서 최대 3개(긴 숫자는 2개)와 `+나머지 개수`만 보여준다. 마우스오버·키보드 포커스·터치 시 전체 PID를 조회하며 Escape 또는 다른 영역 클릭으로 닫는다.

1.10.1은 `PID · 관측 · 편집`을 각각 분리하고 편집을 맨 오른쪽에 고정한다. 관측 열은 상태·시각을 표시하며 마우스오버·포커스·터치로 수정 이력과 미관측의 의미를 확인한다. USER에게는 편집 열이 없다. 왼쪽 메뉴 폭 240px(중간 화면 220px)와 메뉴 글자 16px로 본문 공간을 확보한다.

1.9.0부터 PID는 쉼표 없는 개별 숫자 배지로 표시한다. **전체 항목** 옆의 **시스템 서비스 항목 제외** 버튼을 켜면 시스템 서비스 행만 숨기고 제외한 수를 표시한다. 기본은 전체 표시이며 컬럼 선택과 독립적으로 동작한다. 같은 자산의 새로고침·검색에는 선택을 유지하고 다른 자산을 열면 전체 표시로 시작한다. 행 편집 중에는 버튼을 잠가 작성 중인 행을 유지한다.

필터는 자동 후보의 관측 프로세스명·실행 파일로 식별한다. 커널 스레드 이름, 시스템 경로의 systemd·sshd·chronyd/ntpd·RPC/NFS 보조 데몬·네트워크 설정·Avahi·인쇄 데몬 등이 대상이다. 수기 서비스명으로 판별하지 않으며 수동 등록·컨테이너·소유자 미확인 소켓, 별도 APP/opt 경로의 업무 프로세스와 모니터링 서비스는 제외하지 않는다. root 계정·포트 번호·인프라 분류만으로 시스템 서비스로 추정하지 않는다.

이 버튼은 화면 표시만 변경한다. 자산 요약 건수·수기 정보·관측 원본·과거 보고서는 보존하고 XLSX에는 시스템 서비스를 포함한 저장된 전체 항목을 내보낸다.

XLSX는 **다운로드 시점에 저장된 전체 정보**다. 목록의 검색 조건과 서비스 필터는 적용하지 않으며 보관 항목도 포함한다. 편집 중에는 먼저 저장하거나 취소한다. 새 SSH 점검이나 과거 보고서 재판정은 수행하지 않는다.

| 시트 | 내용 |
| --- | --- |
| 내보내기 안내 | 생성 시각(UTC), 자산/서비스/보관 수, 포함 범위와 해석 |
| 자산 목록 | 등록 정보·담당·환경·위치·OS/자원·최근 점검·발견/의심·메모 |
| 서비스 운영대장 | 서버별 SW/버전·계정·APP/DATA/LOG·관측/수기 포트·시작/종료/상태 확인·연계·보관·수정 이력 |
| 포트·PID 상세 | 화면에서 축약한 전체 포트 원문·PID·실행 파일·이미지 근거. 긴 값은 순번/조각 번호로 분할 |

헤더/식별 열 고정·필터·줄바꿈을 제공한다. 수식처럼 시작하는 명령도 텍스트로 저장한다. 셀 길이 제한을 넘는 관측 값은 상세 시트의 같은 항목/순번을 조각 번호 순으로 이어 붙여 원문을 복원한다. SSH 비밀번호·키 등 연결 자격 증명은 내보내지 않는다.

인증된 다운로드 API는 `GET /api/assets/export.xlsx`, `GET /api/assets/{target}/export.xlsx`이며 조회 권한으로 이용한다.

## 수집과 보존 규칙

- 서버당 최근 완료 점검을 바탕으로 작은 자산 요약과 서비스 후보를 DB에 저장한다. 대시보드는 전체 보고서를 매번 읽지 않는다. 최근 100회 이력 밖의 자산도 포함한다.
- 후보는 컨테이너, PID로 연결된 TCP/UDP 소켓 소유 프로세스, JVM, 소유자를 확인하지 못한 소켓이다. 모든 프로세스를 논리 서비스로 단정하지 않는다.
- 컨테이너 이름, 또는 실행 파일·프로세스명·계정·클래스패스·바인딩 조합으로 후보를 식별한다. PID와 컨테이너 ID만 변경되어도 같은 식별 근거이면 작성 내용을 보존한다. 동일 근거의 여러 PID는 후보 한 행에 함께 표시된다.
- 포트·실행 경로·계정·클래스패스·컨테이너 이름이 바뀌면 다른 후보가 생길 수 있다. 자동으로 수기 정보를 옮기거나 유사한 서비스들을 병합하지 않는다.
- 재점검은 관측 필드만 갱신한다. 수기 이름·포트·경로·절차·메모와 보관 여부는 유지한다. 이번 수집에 없는 항목은 **최근 수집 미확인**으로 표시하며 중지/삭제로 판정하지 않는다. 이전 관측값에는 이전 수집 시각을 함께 표시한다.
- 실패한 점검은 기존 자산 스냅샷을 교체하지 않는다. 부분 수집·도구 없음·미수집 사유를 표시하며 관측값을 실시간 상태로 표현하지 않는다.
- Flyway V4는 추가 테이블만 만들며 기존 계정·자격 증명·보고서를 보존한다. 최초 기동 시 기존 대상마다 최신 완료 스냅샷을 한 번씩 읽어 초기 자산 정보를 구성한다. 재판정·SSH 재점검 없이 진행하며 반복 기동해도 수기 정보는 유지된다.

## 분석 재현

개발 PC에서만 `openpyxl`을 사용한다. 앱·대상 서버에 설치할 필요는 없다.

```bash
python3 -m venv .tools/workbook-analysis-venv
.tools/workbook-analysis-venv/bin/pip install openpyxl==3.1.5
.tools/workbook-analysis-venv/bin/python scripts/analyze-asset-workbook.py \
  resources/wPost-body-2026-11-16.xlsx \
  --output resources/asset-1.6.0-check/workbook-analysis.json
```

스크립트는 원본 SHA-256, 시트·컬럼·병합 범위·빈 값·확인 대상 셀 좌표를 기록한다. 파일명은 자료 기준일이며 실제 서버의 최신 상태를 보증하지 않는다. 운영 명령은 실행하지 않는다.

## OS 지원 종료와 전환 대상

1.11.0은 수집된 배포판·버전으로 RHEL·CentOS 7.x를 식별하고 자산 목록에 **OS 업그레이드 필요** 배지를 표시한다. 대시보드/목록의 대상 수 버튼과 보완 상태 필터로 모아본다. 상세와 업로드 미리보기에는 종료일·조치·공식 출처·정책 확인일/표시 기준일을 제공한다. ELS 계약은 자동 확인하지 않으며 지원 상태를 취약점 건수에 더하지 않는다. MD와 XLSX에도 같은 정책 정보를 포함한다.

기존 자산은 기동 시 최근 점검의 OS 근거로 표시 정보를 보완한다. 저장된 점검 보고서·당시 판정·수기 프로필·서비스 절차는 바꾸지 않는다. 현재 정책으로 표시한 상태는 관측 당시의 판정과 별개다. 자세한 식별 우선순위·미확인 범위는 [OS 지원 정책](os-lifecycle.md)을 참고한다.

1.11.0의 서비스 등록/편집 창은 기존 미분류·미들웨어·애플리케이션·공통·보안·백업 분류와 함께 **웹 서버·데이터베이스·컨테이너·캐시·메시징·인프라**를 제공한다. 운영자가 선택한 구분과 자동 관측 종류(프로세스/컨테이너/소켓)는 별개이며 재점검으로 수기 구분을 덮어쓰지 않는다. 저장 후 표·MD/XLSX에서도 같은 분류명을 표시한다.
